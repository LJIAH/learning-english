这些优化中有几个确实可以提炼为简历亮点，关键在于**用技术语言包装**，而不是简单描述"做了优化"：

---

### 值得写的

**1. Three.js 3D 场景性能治理**

> 对 Three.js 全息投影场景进行生命周期管理，通过 `onBeforeUnmount` 递归释放 WebGLRenderer、Geometry、Material 等 GPU 资源；引入 ResizeObserver + `setSize(w, h, false)` 分离绘图缓冲区与 CSS 尺寸，实现画布自适应而不触发循环锁定。

亮点：体现了你对 WebGL 渲染管线和浏览器渲染机制的理解。

**2. GSAP 动画架构优化**

> 将 GSAP 动画选择器从全局类名迁移至 Vue 模板 Ref，消除跨组件动画污染风险；数字滚动动画从 `onMounted` 立即触发改为 ScrollTrigger 视口触发，提升用户可见性与交互体验。

亮点：体现了组件化思维和动画工程化能力。

**3. 前端性能与响应式架构**

> 页面容器从固定宽度改为 `max-width + w-full` 响应式方案，配合 Tailwind 断点实现卡片网格渐进式布局（1→2→3列）；Header 导航基于 `useRoute` 实现动态高亮与数据驱动渲染。

---

### 简历建议写法

不要单独列出来，而是融入项目描述中，比如：

> **英语学习平台（全栈）**
>
> - 基于 Three.js 实现 3D 全息投影首页视觉，封装组件级资源回收机制，避免 GPU 内存泄漏
> - 设计 GSAP 动画 Ref 化方案，解决多页面全局选择器冲突问题，结合 ScrollTrigger 实现滚动驱动的数字计数动画
> - 实现全站响应式布局适配，卡片网格支持 1/2/3 列渐进式断点，Three.js 画布通过 ResizeObserver 自适应容器宽度

---

### 不太值得单独写的

- 按钮 hover 效果、App.vue 清理残留样式 — 这些属于基本功，写上去反而显得经验浅

核心原则：**写你解决的技术问题，而不是你做的 UI 调整**。
