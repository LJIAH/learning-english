这些优化拆开来都是"正确实践"，单独写"做了防抖"不会吸引眼球。但**组合起来包装成一个项目级方案**，是可以成为亮点的。关键在于**怎么描述**。

## 简历怎么写（参考）

> **前端工程化建设**
> 设计并封装了基于 Axios 的统一请求层：通过工厂函数 `createApi` 实现多后端实例的拦截器复用与 config 透传（signal / headers / timeout），结合泛型 `Response<T>` 实现全链路类型推导；在搜索场景中引入 AbortController 取消过期请求、Vue watch 防抖、组件卸载资源清理，解决了竞态覆盖与内存泄漏问题。

## 面试官会追问什么（提前准备）

1. **"为什么要用工厂函数而不是单例？"**
   → 项目对接两个后端（业务 API + AI API），baseURL 不同但拦截器逻辑一致，工厂模式避免重复代码且支持横向扩展。

2. **"AbortController 和请求竞态具体是什么问题？"**
   → 用户快速输入时，第1个请求比第2个晚返回，会用旧结果覆盖新结果。AbortController 在发起新请求前 abort 上一个，Axios 会抛出 CanceledError，catch 中静默忽略即可。

3. **"`Response<T>` 怎么做到类型推导的？"**
   → `request<T>` 辅助函数统一做 `Promise<unknown> → Promise<Response<T>>` 类型断言，每个 HTTP 方法通过闭包复用它，API 层只需声明泛型参数，调用方自动获得类型提示。

**核心结论：** 单独写"防抖/生命周期"太浅，单独写"封装了 Axios"太空。亮点在于**从具体问题（竞态/泄漏）出发，推导出架构层面的统一方案**，这个思考链路才是面试官真正想看到的。
