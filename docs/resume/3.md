### 🔹 架构设计方向

> **封装 Three.js 场景引擎 Composable，实现 3D 渲染逻辑跨组件复用**
>
> - 抽离场景/相机/渲染器/控制器/ResizeObserver/动画循环/资源销毁为通用 Hook，支持宽高比适配、相机位置配置、动画帧回调等扩展点
> - Hologram、ModelViewer 等多个组件复用同一 Hook，消除重复代码

### 🔹 性能优化方向

> **3D 模型预加载 + 显隐切换策略，实现模型切换零延迟**
>
> - 将"销毁 → 重新下载 → 重新解析"改为一次性预加载所有模型到 Scene，切换时仅控制 `visible` 属性
> - 切换耗时从网络 IO 级别（数百 ms）降至帧级别（< 16ms），消除切换白屏

### 🔹 问题解决方向

> **修复 OrbitControls 与自动旋转冲突导致模型偏移问题**
>
> - 定位根因：Hook 的 `autoRotate` 旋转整个 Scene（公转），导致 OrbitControls 的 target 瞄准点失效
> - 方案：改为在 `onAnimate` 中仅旋转当前模型（自转），并通过 Box3 包围盒动态校准 controls.target 至模型几何中心

### 面试追问准备

如果面试官深挖，你可以聊：

- **为什么选 Composable 而非组件封装** → 模板灵活性、逻辑组合性、不同页面定制需求不同
- **预加载的内存权衡** → 两个模型同时在 Scene 中，用 `visible` 控制渲染开销，GPU 内存增加但换来切换体验
- **setSize 的 false 参数** → 避免 Three.js 锁定 canvas CSS 尺寸，导致 ResizeObserver 失效
- **Scene 旋转 vs Model 旋转** → Scene 旋转会影响 OrbitControls 坐标系，模型自转不影响
